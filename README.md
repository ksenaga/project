# タスク管理システム

## 概要

チーム内のタスクを登録・管理し、プロジェクトやタスクの進捗を把握するためのタスク管理システムです。

タスクの対応内容・修正理由・Git URL・メモなどを記録し、後から修正内容や対応方法を確認できるようにします。

## 目的

本システムは、チーム内のタスク管理を行うことを目的としています。

また、React・Node.js・Express・MySQLを使用し、フロントエンドからバックエンド、データベースまで一通り実装することで、Webシステム全体の仕組みを理解することを目的とします。

## 主な機能

### 認証

* ログイン
* ログアウト
* ログイン状態の保持（有効期限 1 日）
* ログインの失敗回数の制限（5 回続けて失敗すると 15 分間ロック。管理者が解除できる）

### 通知

* 画面上の通知（プロジェクトへの参画・タスクの担当・レビュー中への移動・中止依頼・コメント・メンション・期限が迫っている）

### ユーザー管理

* ユーザー一覧（参画プロジェクト数を表示）
* ユーザー詳細（参画しているプロジェクト名を表示）
* ユーザー登録
* ユーザー編集
* ユーザー削除
* 自分のアカウント編集
* アイコン画像の設定（担当者・コメントなど、アイコンを表示するところすべてに反映）

### プロジェクト管理

* プロジェクト一覧（フェーズ・進捗度・期限・メンバーを表示）
* フェーズの変更（管理者・担当しているリーダー）
* プロジェクト作成
* プロジェクト編集
* プロジェクト削除
* プロジェクトメンバー管理（作成・編集時に選択）
* 変更履歴（誰が名前・詳細・期限・メンバー・フェーズを変えたか。詳細モーダルのアコーディオンで表示）

### タスク管理

* タスク一覧（ヘッダーから開く。担当しているタスクをプロジェクトをまたいで期限順に表示。期限の色ごとの件数・絞り込み）
* タスク一覧（ボード表示と、表のリスト表示を切り替え。リスト表示は列で並び替え）
* タスク登録
* タスク詳細
* タスク編集
* タスク削除
* タスクのコピー
* 担当者設定（複数人）
* タグ付け（バグ・修正・要望・改善・新規・調査・問い合わせ・緊急）
* ステータス管理（ドラッグ&ドロップで変更）
* ボードのリストの追加・名前の変更・並べ替え・削除（管理者・担当リーダー）
* 絞り込み（文字・担当者・タグ・画面名・期限・期限の色の複数条件）
* 期限の色分け（7日以内は赤、8〜14日は黄色、15日以上は緑）
* 画面名の管理（プロジェクトごと。タスクではプルダウンで選択）
* 修正内容・修正理由・Git URL・メモの記録
* 修正内容への画像の貼り付け（原因となる画面のスクリーンショットなど。Ctrl + V・ドラッグ＆ドロップ）
* コメント（やり取り）と、タスクの作成・移動・変更の自動記録（変更履歴）
* コメントの「#ID」・URL から別のタスクやページを別タブで開く
* コメントでのメンション（「@」で候補を出し、メンションされた人に通知）
* 同時編集の確認（ほかの人が先に更新していたら保存せずに知らせる）

## 利用者

* 管理者
* リーダー
* 一般ユーザー

## 技術構成

* Frontend: React / TypeScript / MUI / React Router / dnd-kit（ドラッグ&ドロップ・並べ替え）/ Vite
* Backend: Node.js / Express / TypeScript / Knex（マイグレーション・クエリ）
* Database: MySQL 8.4（Docker）
* Authentication: JWT（httpOnly Cookie に保存）/ bcrypt（パスワードのハッシュ化）

## ディレクトリ構成

```text
frontend/src
  pages/        画面（ログイン・プロジェクト一覧・タスク一覧・ユーザー一覧）
  components/   ダイアログ・カードなどの部品
  api/          バックエンド API の呼び出し
  auth/         ログイン状態の管理
backend
  src/routes/        URL と controller の対応
  src/controllers/   リクエストの受け取り・入力チェック
  src/services/      業務ルール・権限チェック
  src/repositories/  DB アクセス
  src/middlewares/   認証（JWT）・権限・エラー処理
  db/migrations/     テーブル定義（テーブルごとに 1 ファイル）
  db/seeds/          初期データ（管理者）
plan/           要件定義・画面設計・DB設計・API設計
```

## 開発環境

### 必要なもの

* Node.js（v24 で動作確認）
* npm
* Docker（MySQL を動かす）

### セットアップ

```bash
# 1. DB を起動
docker compose up -d

# 2. バックエンド
cd backend
npm install
cp .env.example .env
# .env の JWT_SECRET に `openssl rand -hex 32` で生成した値を入れる
npm run migrate   # テーブルを作成
npm run seed      # 管理者（admin / admin）を登録
npm run dev       # http://localhost:3000

# 3. フロントエンド（別のターミナル）
cd frontend
npm install
npm run dev       # http://localhost:5173（/api はバックエンドに転送される）
```

ブラウザで http://localhost:5173 を開き、`admin` / `admin` でログインする。

### マイグレーション

| コマンド（backend で実行） | 内容 |
| --- | --- |
| `npm run migrate` | 未適用のマイグレーションを適用 |
| `npm run migrate:rollback` | 直前の適用を取り消す |
| `npm run migrate:status` | 適用状況を表示 |
| `npm run migrate:make -- <名前>` | 新しいマイグレーションを作成 |
| `npm run seed` | 初期データを登録（何度実行しても重複しない） |

## 開発方針

本システムでは、既存のフレームワークに依存して実装するのではなく、フロントエンド・バックエンド・データベースの責務や処理の流れを理解しながら開発する。

要件定義 → 画面設計 → DB設計 → API設計 → 実装の順に進める。
